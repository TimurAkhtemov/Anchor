# LLM Copilot Briefing — Design

_Date: 2026-07-10 · Status: approved design, pre-implementation._
_Replaces the deterministic v0 briefing in `app/app.py`'s sidebar (v0 code is retained
as the fallback renderer, not deleted). Realizes the first milestone of
`docs/roadmap_ai_portfolio_analyst.md`._

## Goal

Replace the deterministic Copilot briefing with an LLM-written daily portfolio
briefing that keeps v0's honest-numbers property: **every numeric claim must come
from the served marts.** News may inform qualitative context only. The briefing is
generated at pipeline time by a local LLM and served as an artifact the app renders.

## Locked decisions (with rationale)

1. **Privacy — local-only for real.** Real-portfolio briefings may only ever be
   generated by a local provider; the data structurally never leaves the machine,
   mirroring the `prod-private` isolation guarantee. Demo world may use any
   provider. Hosted-API-for-real is a future explicit opt-in decision, not a
   config accident. Enforced in code (providers declare `is_local`; the generator
   refuses `portfolio=real` with a non-local provider) and regression-tested.
2. **Call site — pipeline-time artifact.** Generation happens in the pipeline, not
   the app. Fits the project principle (analysis lives in the data layer), lets the
   demo briefing ship inside the committed snapshot (live Streamlit Cloud demo shows
   it with zero keys/cost), and keeps failures out of the user path.
3. **Horizon — horizon-agnostic, grain `(date)`.** One briefing per refresh weaving
   all three horizons (1M/YTD/1Y) together, like a real analyst note — richer than
   any single-horizon view and the first thing the LLM can do that v0 structurally
   could not. The artifact is keyed by a `horizon` column (`'all'` in v1) so
   per-horizon rows are an additive change later. The sidebar briefing stops
   reacting to the horizon radio; the radio still drives sparklines/tables.
4. **Provider — Ollama, model `qwen3:30b-a3b-instruct-2507-q4_K_M` by default.**
   Already installed locally; fast MoE inference; the `-instruct-2507` variant is
   non-thinking (clean output, no `<think>` tags). Model name comes from `.env`
   (`ANCHOR_BRIEFING_MODEL`), so swapping models is config, not code. The provider
   seam is our own tiny interface — **not** an OpenAI-compatible shim — so a future
   `AnthropicProvider` uses the official SDK. v1 ships the Ollama adapter only.
5. **Grounding — marts + ticker news.** All five served marts are the numeric
   backbone; yfinance news headlines for held tickers add qualitative market
   context. Rule: numbers from marts only; news for color only, attributed.
6. **News fetching — at generation time, not bronze.** The generator pulls
   headlines live (verified shape: `yf.Ticker(t).news` → items with a nested
   `content` dict carrying `title`/`summary`/`pubDate`/`provider`), recency-filtered
   (≤7 days) and capped (3/ticker, ~20 total). The headlines used are persisted in
   the artifact as the audit trail. A `raw_yfinance_news` bronze ingestion remains a
   documented future option if news history ever becomes a feature (sentiment,
   alerts).

## Architecture

The briefing is a **served table**, written into the active marts dataset:

```
marts (BigQuery) ──┐
                   ├─→ app/generate_briefing.py ──→ copilot_briefing (BQ table, same dataset)
yfinance news ─────┘        (local LLM via Ollama)          │
                                                            ├─→ export_snapshot.py adds it to TABLES
                                                            │     → app/snapshot/copilot_briefing.parquet (demo, committed)
                                                            └─→ app reads via data._read("copilot_briefing")
                                                                  → all 4 modes (demo/real × bigquery/snapshot), zero new seam logic
```

- Demo: table lands in `anchor_marts`; snapshot export ships it; the public deploy
  renders it from parquet.
- Real: generated manually after `make build-private`, lands in
  `anchor_marts_private`; the app in real mode reads it live. The existing
  "snapshot is demo-only" guard in `app/data.py` already covers the file path.
- Note: `copilot_briefing` is a serve-layer table not built by dbt — it will not
  appear in dbt lineage. Documented limitation, acceptable for v1.

### Artifact schema (grain: one row per `horizon`; v1 writes one row)

| column | contents |
|---|---|
| `horizon` | `'all'` (v1) |
| `briefing_md` | the markdown the sidebar renders |
| `as_of_date` | the shared market-calendar date the numbers describe |
| `generated_at` | wall-clock generation timestamp |
| `provider` | e.g. `ollama` |
| `model` | e.g. `qwen3:30b-a3b-instruct-2507-q4_K_M` |
| `sources` | JSON list of headlines fed to the prompt (ticker, title, provider, pubDate) |

### Pipeline placement

New Makefile targets `make briefing` (demo) and `make briefing-real`.
`make refresh` becomes ingest → build-prod → **briefing** → snapshot.
**Strict failure policy:** a briefing failure halts refresh — the snapshot never
exports a partially-fresh state. The generator only `WRITE_TRUNCATE`s after
validation passes, so a failed run leaves the previous briefing intact.
Dagster: a `copilot_briefing` asset between the dbt assets and `snapshot_parquet`
is a follow-up, not v1 (the local graph would require Ollama running).

## Components

Two new files, following the `export_snapshot.py` convention (importable functions
+ thin CLI, Dagster-wrappable later):

**`app/briefing.py`** — the library:
- `BriefingProvider` protocol: `name: str`, `is_local: bool`,
  `generate(system: str, prompt: str) -> str`.
- `OllamaProvider`: POSTs to `localhost:11434/api/chat` (host overridable via
  `OLLAMA_HOST`); model from `ANCHOR_BRIEFING_MODEL` (default the qwen3 instruct
  above). `is_local = True`.
- `build_context(marts, news) -> str`: **pure function** of DataFrames → the dense
  prompt packet — as-of date, regime + 4 macro indicators, 11-sector table,
  allocation by asset class, per-holding rows (weight, 1M/YTD/1Y returns,
  benchmark relatives per axis, unrealized gain, root/valuation flags), then
  per-ticker headlines. Purity is the load-bearing testing decision: "did the
  right numbers get into the prompt" is a deterministic CI test with no LLM.
- `fetch_news(tickers) -> list`: held tickers only (not benchmark ETFs), ≤7 days,
  ≤3/ticker, ~20 total; parses the nested `content` shape.
- System prompt: Anchor's analyst voice; ~3 short paragraphs of markdown in the
  macro → sector → holdings reading order; every numeric claim verbatim from the
  DATA section; NEWS only for qualitative context, attributed; omit rather than
  invent when data is missing.

**`app/generate_briefing.py`** — the CLI: `--portfolio demo|real`; reads marts from
the corresponding dataset, fetches news, generates, validates, writes the table.
Enforces the privacy rule: `portfolio=real` requires `provider.is_local`.

## App integration

- **`app/data.py`**: new `copilot_briefing() -> pd.Series | None` reader. `None`
  when the table/parquet doesn't exist — the only served table whose absence is a
  legitimate state; all other marts keep hard-failing.
- **`app/app.py` sidebar**: briefing present → render `briefing_md` in the existing
  styled card + provenance caption ("Generated {as_of_date} · {model} · {provider}
  · N headlines"). Briefing absent → deterministic v0 lines (extracted into a
  fallback function, kept alive as the graceful-degradation path). If the
  briefing's `as_of_date` is older than `as_of_calendar`'s current date, the
  caption shows an explicit staleness marker. `chat_input` stays disabled.

## Validation (runs before the table write)

Perfect grounding verification is impossible; we layer cheap deterministic checks
on prompt discipline plus the audit trail.

Hard failures (block the write, non-zero exit):
- empty output or outside sane length bounds
- `<think>` tag leakage (guards against swapping in a thinking-mode model)
- `portfolio=real` with a non-local provider

Warnings (logged, promotable to hard failures once the false-positive rate is
known): numeric audit — every percentage in the briefing should appear in the
context packet (rounding-tolerant); mismatches print both sides for eyeballing.

## Testing (CI has no Ollama — everything runs against fakes)

`tests/app/test_briefing.py`:
1. `build_context` fixtures → packet contains the exact numbers from input frames.
2. News parsing against a canned nested-`content` payload; no live network.
3. `FakeProvider` end-to-end: generate → validate → row matches the artifact schema.
4. Validator units: empty, `<think>`, numeric-audit paths.
5. Privacy structural: `generate(portfolio="real", provider=<non-local fake>)` raises.

`tests/app/test_snapshot_privacy.py` extension:
6. Every ticker in the committed briefing's `sources` JSON ⊆ demo + benchmark
   allowed set. (Honest limitation: `briefing_md` free text cannot be exhaustively
   scanned for unknown tickers without false-positives on words like "CEO"; the
   structured `sources` column is the enforceable surface, and the demo briefing is
   generated from demo marts by construction.)

The live-model quality loop is manual and local: `make briefing`, read, tweak the
prompt, repeat — the iteration loop the local model exists for.

## Configuration

`.env` additions (gitignored, like the SnapTrade keys):
- `ANCHOR_BRIEFING_MODEL` — default `qwen3:30b-a3b-instruct-2507-q4_K_M`
- `OLLAMA_HOST` — optional, default `http://localhost:11434`
- (future) `ANTHROPIC_API_KEY` — only read by the future `AnthropicProvider`

## Post-ship revision (2026-07-11)

Decision 4's default model flipped to **`gemma4:31b`** after a same-packet A/B:
qwen3:30b-a3b (MoE, ~24s) kept producing scope/direction prose slips that the
numeric audit structurally cannot catch (grounded numbers, wrong "across all
horizons"/axis words), while gemma4:31b (dense, ~4 min) quoted the packet's
ahead/behind/in-line verdicts and news attributions item-exactly with zero
audit warnings. Latency is irrelevant at the pipeline call site (decision 2),
so accuracy wins. qwen3 remains one `ANCHOR_BRIEFING_MODEL` away.

## Out of scope for v1 (documented follow-ups)

- `AnthropicProvider` (official SDK, `is_local=False`) — the go-live/API path;
  demo world may use it, real world requires a new explicit opt-in decision.
- Per-horizon briefing rows (additive on the `horizon` key).
- Bronze news ingestion (`raw_yfinance_news` + staging) if news history becomes
  a feature.
- Conversational Q&A (the disabled `chat_input`), alerts, custom position groups
  (per the roadmap doc).
- Dagster `copilot_briefing` asset.
